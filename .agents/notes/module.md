# GuiyuX 桌面收纳

面向 Windows 的低内存常驻桌面工具，参考 [Booki](https://github.com/punkable/booki) 的拖入固定、分组与快速打开体验。界面支持简体中文和英文。视觉方向是通过胶囊和卡片的形态变化表现展开、归类和收起。

GuiyuX 的「合页」标志由两片相对的纸页组成 X，使用石墨灰与暖纸白。Windows 图标保留暖纸白的 X，外缘和页间留白均透明。程序内嵌多尺寸图标，供资源管理器、任务栏和设置侧栏共用。

## 收纳方式

| 方式 | 用户操作 | 版本范围 |
| --- | --- | --- |
| 灵动岛 | 可停靠在主屏工作区四边。常驻时点击胶囊，自动隐藏时移入边缘圆弧，即可打开快捷栏并选择分组。点击图标打开条目，把文件拖到岛上可选择分组投放。 | 第一版唯一的收纳入口 |
| 卡片展开 | 多个分组封面摆在桌面上，用户按位置找到分组，点击封面原位展开，再取用其中的内容。 | 后续构想 |
| 分组卡牌 | 每个分组对应一张卡牌。用户浏览多张卡牌、选中目标组，再点击牌面上的图标打开条目。翻页、滚动等浏览手势待设计。 | 后续构想 |

三个入口共用分组、条目和排序。收藏保存应用、文件、文件夹或网址的引用；移除收藏时保留源文件。

## 当前工程

Rust 常驻核心用 Win32 绘制灵动岛和右键菜单，设置窗口按需启动。默认在顶部常驻，胶囊是高 18 像素的毛玻璃短条。指针悬停时，短条从中心向两侧舒展并提亮，移开后恢复。悬停底色在约 140 毫秒内渐变。指针移入快捷栏或网格时，图标绕自身中心轻摆一次，约 320 毫秒后回正。文字和点击区域保持在原位。网格图标和导航按钮以较亮的底色提示键盘焦点。快捷栏默认显示六个快捷入口与「更多」。11 个分类共用一套无外框的单色线形符号，收起箭头在静止时使用低对比度，仅悬停、按下或键盘聚焦时提亮。设置页以线形符号区分类别，岛上固定的文件和应用优先显示系统图标。常驻模式下，点击胶囊后快捷栏从停靠边中央展开，图标渐显。快捷栏末端的箭头指向停靠边，点击箭头或岛外可收起。悬停提示从控件朝屏幕内侧弹出。分类详情左侧的箭头返回上一层。关闭系统界面动画时，图标保持静止，悬停和收展直接切换到目标状态。快捷栏和网格都在图标下显示一行名称。应用快捷方式省略 .lnk 或 .url 后缀，文档保留扩展名，过长的名称以省略号收尾。分类详情最多四列三行，方向键可按图标位置选择，Page Up 和 Page Down 可翻页。悬停可查看完整文件名及所在目录，或查看分类的收藏数。投放后在胶囊内短暂显示结果。右键菜单的「设置…」打开石墨灰设置窗口，左侧可切换收纳、快捷栏、整理规则、外观和界面语言。「界面语言」位于设置中，支持整行点选和方向键切换，选择即时保存。跟随系统一行显示实际采用的语言。右键菜单使用 14 像素文字和 16 像素图标，悬浮提示使用 12 像素文字。菜单外沿半径为 8 像素，各菜单项共用 4 像素圆角的悬停底色。选择红色的「退出」直接结束程序。配置与收藏保存在本地 JSON 中。同一配置目录使用实例锁，写入时原子替换文件。构建入口、运行方式和源码职责见[工程说明](../../README.md)。

灵动岛和右键菜单使用 Win32 控件和 GDI 离屏绘制。图标、悬停底板与导航箭头在六倍采样画布中合成后取平均。Windows 读取文件图标时可能再次请求绘制，嵌套绘制暂用分类符号，外层绘制完成后显示系统图标。胶囊、悬浮提示和右键菜单按像素覆盖率合成透明圆角。菜单的外沿与内缩高亮使用同心圆弧。自绘菜单弹出时临时关闭原生矩形投影，避免浅色背景从圆角与投影之间露出。菜单显示后立即恢复原有类样式。Win32 处理菜单命中测试、键盘导航和辅助功能。窗口尺寸与画面同时提交。Direct2D / DirectWrite 是后续定制视觉方案。收纳文件夹与快捷入口已接入灵动岛。卡片视图和性能预算仍待实现或验证。

## 设置窗口与常驻核心

右键菜单的「设置…」启动同目录的 `guiyux-settings.exe`。这个 Tauri 2 窗口用 WebView2 加载内嵌的 React/CSS，提供收纳、快捷栏、整理规则、外观和界面语言。再次打开会恢复并聚焦已有窗口。关闭设置后，宿主和它创建的 WebView2 进程一并退出，仅运行灵动岛时只需核心进程。

设置窗口左上角显示 GuiyuX 标志，当前页标题右侧并排放置最小化、最大化或还原、关闭按钮。正文滚动时，页标题和按钮始终可见。拖动侧栏标志或页标题区域可以移动窗口，双击可以在最大化与还原之间切换。拖动边框或四角可调整大小。最小化后可从任务栏或灵动岛的设置入口恢复。

Windows 有时会把进程的关闭请求发给 Tao 的辅助窗口。宿主把这类请求转到设置窗口，启动期间收到的请求等到页面就绪再处理。这样待保存的修改可以走完正常关闭流程，WebView 的消息通道也会保留到窗口退出。

两个进程通过启动时继承的匿名管道交换请求、结果和变更通知。Rust 核心在灵动岛的消息线程上处理配置、收藏和 Windows Shell 分类操作，沿用已有 JSON 格式和原子写入方式。滑杆拖动时只更新外观预览，松手后才保存。设置进程在预览中途断开时，灵动岛恢复已保存的外观。规则预览在配置副本上计算，保存或立即整理时才更新收藏。

下拉列表和滑杆由同一 WebView 合成，弹层和触发器共享圆角、颜色及缩放。这样可避开原生弹出窗口与 GDI 控件分别重绘时的白色首帧及拖动残影。代价是首次打开设置须启动 WebView2，发布时须配套两个可执行文件。

## 灵动岛与菜单外观

「设置 → 外观」可分别选择停靠位置和显示方式。灵动岛停在主屏工作区的上、下、左或右边中央，上下横排，左右竖排。常驻模式下点击胶囊展开。自动隐藏时只露出贴边的 5 像素圆弧。鼠标移入圆弧，第一帧即显示可操作的完整快捷栏，键盘焦点留在当前窗口。移出快捷栏约 260 毫秒后开始收回，收回途中再次移入可立即展开。菜单和拖放期间保留当前界面。设置演示共用收起圆弧的外观参数，悬停时按当前固定顺序显示快捷栏缩略图。拖入文件可悬停展开分类。两个选项即时保存，旧配置沿用顶部常驻。

背景效果和透明度由灵动岛与右键菜单共用，沿用已有配置，默认使用 30% 毛玻璃。滑杆支持实时预览和方向键微调，右侧输入框可直接填写 0 到 100 的任意整数。外观页和整理规则页的下拉列表使用石墨灰底、圆角高亮和当前选项勾选标记，支持方向键选择、Enter 确认和 Esc 收起。

收起的胶囊、快捷栏、「更多」网格和分类详情都随外观设置即时更新。Windows 合成器柔化岛后桌面，岛面叠加冷灰渐变和细边缘高光。分类名和文件名在独立前景层按屏幕像素绘制，高透明度时加细暗边以保持浅色桌面上的可读性。透明模式直接透出背景，0% 恢复实色。系统无法提供背景模糊时退回透明，高对比度模式下岛面使用实色。

普通菜单、图标菜单及子菜单每次打开时读取 Windows 应用主题，浅色用雾白底和深灰字，深色用石墨灰底和浅色字。菜单采用细描边、分隔线和内缩的圆角悬停高亮。毛玻璃取样弹出位置的局部背景，菜单以所选透明度的一半透出背景，让文字在明暗桌面上都容易辨认。透明模式直接使用所选透明度。鼠标松开或按回车确认高亮命令时，先收起整组菜单再执行命令，避免选中行淡出时留下黑块。系统高对比度模式使用原生菜单。视觉参考见 [Booki 的 Dock 菜单](https://github.com/punkable/booki/blob/d4eaff03f30e422e26f792d9e366e1f03e4c5054/src/styles/menus.css)。

## 首版设计建议

优先跑通拖入、分组、打开、收起和重启恢复。其他候选功能包括搜索、托盘入口、全屏避让、显示器选择、按屏幕缩放以及失效路径修复。界面文字随系统语言初始化，并支持手动切换；用户命名的分组保留原文。

## 收藏分类与自动整理

按用途识别应用，按内容识别文件。每项只进一个分类。「立即整理」同时处理已有收藏和当前桌面的文件、文件夹及快捷方式。打开条目时使用原路径，快捷方式保留自己的启动参数。

| 默认分类 | 内置规则与典型条目 |
| --- | --- |
| 办公通讯 | 微信、企业微信、飞书、Teams、Outlook、WPS 等沟通与办公应用。 |
| AI 助手 | ChatGPT、Claude、DeepSeek、豆包等通用助手。专用工具按主要用途归类。 |
| 开发工具 | VS Code、Visual Studio、Git、Cursor、Claude Code 等开发工具，以及 .rs、.py、.code-workspace 等源码或工程文件。 |
| 设计创作 | Photoshop、Figma、Midjourney 等创作工具，以及 .psd、.ai、.fig 等设计源文件。 |
| 实用工具 | 已识别的通用工具，如浏览器、7-Zip、PowerToys。 |
| 文档 | 沿用现有文档格式，包括 .docx、.xlsx、.pdf、.md 等。 |
| 图片 | 沿用现有图片格式，包括 .png、.jpg、.svg 等。 |
| 影音 | 现有音视频格式和已识别的播放器，如 .mp4、.flac 和 VLC。 |
| 压缩包 | .zip、.7z、.rar、.tar.gz 等归档文件。 |
| 文件夹 | 普通目录，以及目标为目录的快捷方式。 |
| 其他 | 收纳剩余条目，包括缺少识别信息的程序、目标失效的快捷方式和未知格式。 |

**规则怎样匹配**

1. 手动指定的分类优先。条目右键可选「移至分类或文件夹」，以后整理时保留该选择。选「跟随规则」可解除手动指定，自动整理开启时会立即重新判断，关闭时留待下次整理。
2. 再查用户规则。「设置 → 整理规则」每条规则选一个条件（应用标识、完整文件名或扩展名）和一个目标分类。名称和扩展名忽略大小写，多条命中时取列表中靠前的一条。例如给 .drawio 建一条「设计创作」规则，即可同时覆盖已有和新收藏。
3. 最后查内置规则。对 .lnk 读取目标，按目标的应用标识、目录类型或文件格式分类。程序依次匹配应用 ID、产品名和已知程序名。文档名中出现应用名称不会触发应用规则。例如「开会.lnk」指向 Teams 时进「办公通讯」，「微信会议纪要.docx」进「文档」。网页快捷方式（.url）按目标网址的域名匹配。ChatGPT 桌面版通过应用标识识别，指向 `chatgpt.com` 的网页快捷方式通过域名识别，两者都进「AI 助手」。仅有「ChatGPT」的名称、目标无法识别且没有其他规则命中时，归入「其他」。其余未命中项也归入「其他」。

**自动整理开关**

「设置 → 收纳 → 自动整理新收藏」默认开启，开关状态和收藏位置在重启后恢复。拖到胶囊、没有指定落点时，开启就按规则归类，关闭就收入「其他」并提示「已收纳到其他」。拖入和切换开关都保留桌面原有的图标显示状态。旧版只保存路径的收藏在升级后首次载入时按默认规则归类。

**整理桌面与恢复图标**

在胶囊右键菜单或「设置 → 收纳」选择「立即整理」，核心读取 Windows 指定的个人桌面和公共桌面的第一层，支持重定向的桌面目录。按资源管理器的隐藏项目设置筛选，略过 `desktop.ini`。文件夹整体收入分类，桌面快捷方式保存为快捷方式本身。已有手动归属和快捷栏顺序优先。重复整理会补收后来放入桌面的项目，每个原路径只收藏一次。规则预览中，新项目的来源显示为「桌面」。「保存规则」仅保存规则，「保存并整理」应用新规则并执行一次桌面整理。

核心先将收藏引用和恢复标记原子写入配置，再通过 Windows 桌面视图的 `FWF_NOICONS` 收起整层图标。回收站、此电脑等系统入口随桌面收起。原路径、文件属性和文件夹内容照常可从资源管理器访问。收起期间，新放到桌面的项目也随该视图隐藏，再点「立即整理」即可收入灵动岛。

右键菜单和收纳设置均提供「恢复桌面图标」，恢复后分类收藏仍可使用。正常退出时，GuiyuX 会恢复自己收起的图标。如果整理前图标已由用户隐藏，正常退出会保留这个选择。核心意外中断后，下次启动仍可使用恢复入口。

**快捷文件夹与图标放置**

在「设置 → 快捷栏」可新建、命名和调整收纳文件夹的显示顺序，也可选择一个本地目录作为快捷入口，日后可在此更换目录。点击自建文件夹查看其中的收藏，点击本地目录入口则在资源管理器中打开。移除快捷入口保留原收藏；删除自建文件夹时，其中的收藏统一收回「其他」。

把桌面图标拖到胶囊上方可展开投放区，岛内已有图标也可直接拖动。松手前显示目标高亮或插入线，两种落点各有明确动作。

| 落点 | 松手后的结果 |
| --- | --- |
| 高亮的分类或自建文件夹 | 图标归入该组，记录为手动指定。开关关闭时同样可以放入，再次整理时保留归属。 |
| 快捷栏上的插入线 | 在该位置固定可单击打开的独立图标。固定只增加入口，同一收藏仍只有一个归属。 |
| 组内图标左侧或右侧 | 将图标放到竖向插入线位置并记住顺序。跨组拖入时同时更新手动归属。组内未手动调整前沿用最近收藏在前的顺序。 |

快捷栏默认显示办公通讯、开发工具、文档、文件夹、AI 助手和设计创作六个入口，另设「更多」和收起按钮。首次升级时沿用旧版默认顺序并补齐两项，自定义快捷栏保留原样。用户可拖动快捷文件夹或独立图标调整位置，超出首屏的入口在「更多」中可达。点「更多」时快捷栏保持原位，同一窗口朝工作区内侧展开最多四列的图标网格，显示其余分类及溢出的快捷入口。每页最多十二项，翻页只切换网格。再次点「折叠更多」或按 Esc 回到快捷栏，末端箭头收起整个灵动岛。「其他」在网格末尾，已固定到首排时从首排打开。条目右键提供「移至分类或文件夹」和「固定到快捷栏」，也可以用菜单完成放置。

## 技术路线与验证

已选定 Rust 常驻核心与 Tauri 2 设置宿主。Win32 负责胶囊、展开面板、系统菜单和拖放。React/CSS 负责设置表单、弹层和交互状态。性能评估分开记录常驻核心与设置打开时的整个进程树。灵动岛的后续渲染调整仍需验证中文排版、键盘焦点、读屏和透明区域命中。

界面回归入口为 `build.ps1 -VerifyOnly`。测试线程通过 `SetThreadDesktop` 进入单独创建的桌面。常驻核心及其设置宿主使用临时程序和临时配置，Windows 作业对象负责在测试失败时收尾。测试用原生窗口消息完成展开、翻页与关闭，WebView 的交互用例可通过页面接口驱动。测试期间用户可继续在原桌面使用鼠标和键盘。

首轮原型建议在 Windows 11 x64 上放入 100 个收藏，记录收起五分钟后的专用工作集、专用提交量和空闲 CPU 时间，再测连续开合 100 次后的变化。同机以相同条目对照 Booki，计入其相关子进程。40 MiB 是收起时专用工作集的探索预算，实际占用和相对节省量待测。
